| Код | Требования | Комментарий |
|-----|------------|-------------|
| F | Функциональные (Functionality) | |
| F1 | Клиент без регистрации может посмотреть на сайте доступные депозитные продукты с актуальными ставками. | |
| F2 | Клиент может подать заявку на депозит на сайте, указав Ф. И. О. и номер телефона. | После этого с клиентом связывается менеджер кол-центра. |
| F3 | Менеджер кол-центра может просмотреть заявку на депозит и предложить клиенту особые условия. | |
| F4 | Клиент в интернет-банке видит актуальные депозитные предложения и персонализированные ставки. | |
| F5 | Клиент в интернет-банке может подать заявку на открытие депозита, указав счёт и сумму. | Операция подтверждается SMS-кодом. |
| F6 | Ставки по депозитам должны храниться централизованно, а не только в XLS-файлах. | Возможный вариант реализации — в АБС. |
| F7 | В рамках MVP заявку на открытие депозита обрабатывает сотрудник депозитного бэк-офиса. | Сотрудник подтверждает условия депозита в АБС. |
| F8 | Клиент получает SMS-уведомление после подтверждения ставки и после открытия депозита. | |
| F9 | На сайте клиент может ознакомиться с кредитными предложениями по примерным условиям. | Полная информация об условиях кредита хранится в кредитном конвейере. |
| F10 | Клиент может подать заявку на кредит на сайте, указав Ф. И. О. и номер телефона. | |
| F11 | Если клиент на сайте указал паспортные данные, система должна выдать предварительное решение по кредиту. | Для нового клиента используются данные бюро кредитных историй. |
| F12 | После подачи кредитной заявки на сайте клиент получает SMS о необходимости прийти в отделение для идентификации. | |
| F13 | Сотрудник отделения может продолжить работу с кредитной заявкой, ранее созданной на сайте. | Если заявки не было, сотрудник создаёт новую заявку через АБС. |
| F14 | Клиент в интернет-банке видит доступные кредитные предложения и предодобренное предложение, если оно есть. | |
| F15 | Клиент в интернет-банке может подать заявку на кредит, указав счёт зачисления средств и данные для заявки. | Операция подтверждается SMS-кодом. |
| F16 | После подачи заявки по предодобренному предложению выполняется повторная проверка скоринга по упрощённой процедуре. | Если ситуация по клиенту изменилась. |
| F17 | Клиент получает SMS-уведомления об изменении статуса кредитной заявки. | |

| U | Удобство использования (Usability) | |
| U1 | Интерфейс сайта и интернет-банка должен быть удобным для просмотра продуктов и подачи заявок. | |
| U2 | Интерфейсы должны соответствовать дизайн-системе компании. | Используются привычные цвета и брендированные элементы. |
| U3 | Клиент должен видеть понятный результат после подачи заявки. | Например: заявка принята, ожидает обработки, необходимо прийти в отделение. |
| R | Надёжность (Reliability) | |
| R1 | Повторная отправка заявки в АБС должна выполняться не менее 5 раз с экспоненциальной задержкой. | |
| R2 | Для СМС подвержждений предусмотрена повторная отправка сообщения при временной ошибке оператора. | |
| R3 | Доступность сервисов должна составлять 99,9%. | |
| R4 | Сервисы должны соответствовать RTO (Recovery Time Objective) не более 1 часа и RPO (Recovery Point Objective) не более 1 минуты | |
| R5 | Сервисы интернет-банка должны быть доступны при сбое основного ЦОД. | Нужно учитывать наличие резервного ЦОД. |
| R6 | В новом процессе интернет-банк не должен напрямую работать с API или БД АБС. | |
| R7 | Нужно предусмотреть горизонтальное масштабирование и распределение нагрузки между серверами, приложениями и ЦОД. | АБС масштабируется только вертикально. |
| R8 | При временной недоступности АБС заявка клиента не должна теряться, а сохраняться в DLQ с помощью паттерна outbox. | |

| P | Производительность (Performance) | |
| P1 | Для просмотра списка депозитных продуктов время ответа p95 не должно превышать 500 мс, а p99 1 сек. при 10 тыс. RPS | |
| P2 | При создания заявки на депозитные продукты время ответа p95 не должно превышать 700 мс, а p99 1.5 сек. при 10 тыс. RPS | |
| P3 | Сервисы должны выдерживать временную нагрузку во время маркетинговых кампаний до 20 тыс. RPS без возвращения ошибок в ответе | |
| P4 | Получение ставок и условий не должно выполнять тяжёлые запросы к АБС при каждом обращении клиента. | |
| P5 | Систему кредитного скоринга нельзя нагружать дополнительными массовыми предрасчётами в рабочие часы. | Скоринг уже испытывает повышенную нагрузку. |

| S | Сопровождаемость (Supportability) | |
| S1 | Необходимо подготовить документацию API в формате Swagger не ниже версии 3. | |
| S2 | Документация по процессам должна быть описана в Confluent. | |
| S3 | Для описания диаграмм использовать PlantUML. | |
| S4 | Нужно минимизировать доработки ядра интернет-банка, требующие участия подрядчика. | Особенно для SMS-функциональности. |

| +R | + Ограничения (Restrictions) | |
| +R1 | Нужно максимально использовать технологии, которые уже есть в банке. | Например, MS SQL, Oracle, Java, Python, .NET. |
| +R2 | Новые технологии допустимы, если они совместимы с текущей инфраструктурой и понятны командам банка. | |
| +R3 | Если нужны очереди сообщений, предпочтительно использовать Kafka. | Текущая версия интернет-банка несовместима с Kafka. |
| +R4 | Можно рассмотреть микросервисный подход в рамках функций открытия депозитов и подачи кредитных заявок. | Без полного переписывания интернет-банка. |
| +R5 | АБС масштабируется только вертикально. | Это ограничивает прямую онлайн-нагрузку на АБС. |
| +R6 | Текущий обмен между АБС и кредитным конвейером выполняется раз в сутки, ускорить его нельзя. | Для обработки кредитных заявок в тот же день нужен другой механизм. |
| +R7 | Передача чувствительных данных с сайта и из интернет-банка должна выполняться по протоколу HTTPS с TLS 1.2. | На сайте передаются Ф. И. О., телефон и паспортные данные. |
| +R8 | Новый клиент должен пройти идентификацию в отделении перед оформлением продукта. | Банк не может принять нового клиента без личной проверки документов. |
| +R9 | Доступ сотрудников депозитного и кредитного бэк-офиса к данным должен быть разграничен. | По требованиям безопасности они не должны иметь доступ к данным друг друга сверх необходимости. |
| +R10 | Систему кредитного скоринга не нужно нагружать процессами предварительного расчёта скорингов. | Требование из кредитного направления. |
